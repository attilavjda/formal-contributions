# Summary of changes for run 1801234c-8e6e-4606-b236-11fafa0a83c2
I ran a mechanical, whole-library measurement of Mathlib lemma naming and wrote it up with examples drawn from many different areas.

**New files**
- `naming-survey/Survey.lean` — the survey program (run with `lake env lean naming-survey/Survey.lean`). It reads every constant in the environment, builds the vocabulary of *named definitions* (53 754 distinct last name-components), takes all 217 726 human-written Mathlib theorems (auto-generated declarations filtered out), splits each name at `_`, and classifies each token as GROUNDED (names a definition that occurs in that lemma's statement), ELSEWHERE (names some definition, but not one in this statement) or FREE (no definition of that name exists anywhere). Matching also tries dropping trailing subscripts/primes and adding an `Is` prefix, counted separately.
- `naming-survey/output.txt` — raw output: global counts, top-120 FREE and top-80 ELSEWHERE tokens with examples, per-area statistics and per-area example lists, and a per-area breakdown of 37 watched tokens (`self`, `of`, `diag`, `diagonal`, `cofinal`, `aux`, `tfae`, …) split by whether the token is realised in the statement.
- `naming-survey/REPORT.md` — the write-up.
- `RequestProject/NamingConventionEvidence.lean` — every declaration quoted in the report is `#check`ed here; the file builds against the pinned Mathlib, so no example is asserted without being compiler-checked.

**What the data say**
- Only 70 % of name tokens are the name of a definition occurring in the statement, and only 44 % of lemma names have *all* tokens grounded that way. So "name parts must be named definitions in the statement" is a tendency, not a rule.
- Per-area: structure-heavy areas (CategoryTheory 79 %, Algebra/Homology 80 %, Data/Finset 78 %) name lemmas almost entirely from definitions; notation/shape-heavy areas (Algebra/Order 55 %, Algebra/Divisibility 43 %, Analysis 63 %) much less.
- The non-definition tokens fall into recurring families, each illustrated with examples from several areas: connectives (`of`, 28 494 occurrences); shape words (`self` 2 767 — never grounded, `same` 181, `left`/`right` ~5 200 each, `comm`, `assoc`, `cancel`); arity/variant markers (`iSup₂`, `iInf₂`, `iUnion₂`, `iInter₂` are **not** definitions, while `map₂`, `eval₂`, `image2` are; `₀` for the `GroupWithZero` variant; `'` for primed variants; `aux`); contractions of a qualified name or a phrase (`natCard`, `cardinalMk`, `setIntegral`, `measureReal`, `notMem`, `ciSup`/`csSup`, `biSup`/`biInter`, `mclosure`, `opNNNorm`, `SpecMap`); words for terms written anonymously in the statement (`diag` in `Filter.tendsto_diag`, `Set.range_diag`, `Matrix.IsAdjMatrix.apply_diag`; number words `two` 1 578, `three`, `four`, `half`); area-specific picture words (`pointwise`, `fiberwise`, `tower`, `dominated`, `unitality`, `hexagon`, `preserves`/`reflects`, `intermediate`); eponyms (`ruzsa`, `pluennecke`, `hahn`/`banach`, `young`, `lhopital`, `leibniz`, `lebesgue`); and 1 660 tokens that drop an `Is` (`of_open`, `of_closed`, `of_iso`, `of_compact`), against the modern `is`-ful spelling (`IsCompact.of_isClosed_subset`, `sSup_le_sSup_of_isCofinalFor`).
- Applied to the case that prompted the question: `iSup₂` is itself a pattern token rather than a constant, so a lemma named with it is already naming a shape; `diag` has both grounded uses (`Finset.diag`, `Matrix.diag`, `OrderHom.diag`/`onDiag`, `Functor.diag`) and ungrounded "picture" uses, so a `_diag` suffix is within precedent — and stronger still when the statement is phrased so that `Functor.diag`/`Set.diagonal` actually appears. `_self` (repeated term) and `_same` (coinciding indices) are the real competing spellings, and for the hypothesis suffix Mathlib's own cofinality lemmas favour `…_of_isCofinal` over `…_of_cofinal`.
