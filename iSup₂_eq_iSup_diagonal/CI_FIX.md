# Recommended PR refactor after CI feedback

## Short answer

Keep the PR focused on the diagonal lemma and its three demonstrated callers. Do **not** add the
set-level equality lemma in this PR unless another independent caller is found.

The proposed set argument is mathematically right, with two Lean/API corrections:

1. `IsCofinalFor` already includes the relation; its use is `IsCofinalFor t s`, not
   `IsCofinalFor (· ≤ ·) s t`.
2. In this Mathlib version the subset lemma is named `sSup_le_sSup`, not `sSup_mono`.

Thus the thin set-level helper would be:

```lean
theorem sSup_eq_sSup_of_subset_of_isCofinalFor
    [CompleteSemilatticeSup α] {s t : Set α}
    (hst : s ⊆ t) (hts : IsCofinalFor t s) : sSup s = sSup t := by
  apply le_antisymm
  · exact sSup_le_sSup hst
  · exact sSup_le_sSup_of_isCofinalFor hts
```

This is valid in shape, but it merely combines two existing one-line inequalities. With only the
diagonal theorem as a caller, it is likely too thin for the current PR.

## Why the theorem was renamed

The original name `iSup₂_eq_iSup_diagonal` does not dualize to the requested
`iInf₂_eq_iInf_diagonal`: automatic name translation sees only the final `iSup` component and
produces `iSup₂_eq_iInf_diagonal`. Giving the requested name explicitly then triggers the linter:

> `to_dual` correctly autogenerated target name ...

Using `iSup₂_eq_diagonal` / `iInf₂_eq_diagonal` avoids both problems: the dual names are symmetric,
and the explicit target is genuinely needed rather than redundantly restating an autogenerated
name.
